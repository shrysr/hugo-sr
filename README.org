
* Introduction

This is the source of my personal website, based on hugo.

Visit my website at https://shreyas.ragavan.co

* Workflow

I use [[https://www.gnu.org/software/emacs/][Emacs]] for .. almost everything and use the excellent [[https://github.com/kaushalmodi/ox-hugo][ox-hugo]] package to
maintain the entire contents of my website in a single Org mode file. The
obvious advantage is the ability to work within Emacs, resulting in a friction
free writing and publishing experience.

This repository is pulled every 5 minutes through a cron job on my Linode VPS,
and the static website is served via Apache. The reason I use Apache instead of
the Hugo server, is that I also use the same VPS to serve multiple experimental
sites and wikis. Subsequent to the git pull, the Hugo server is started up to
build from this source repository and I've found it will only copy over updated or
modified files to the public directory served by Apache. Since Hugo generates
the entire site in milliseconds, I can get by with the cron job running every 5
minutes.

Anytime I want to create a blog post or an update, I work on a local hugo server
for previewing the post and the site, and once I commit and push - the cron job
described above will ensure the latest version of the site is deployed. I do not
edit any files of this site directly on the VPS.

It would actually be more efficient to use a service like Netlify for automated
deployment, which would add other benefits and make the process more
robust. That is.. for the future.

* CSS Customizations and Maintenance Notes

** Overview

This site uses a carefully orchestrated system of custom CSS files to achieve specific layout behaviors, particularly for post listings on archive and tag-filter pages. Understanding the CSS loading order and customization architecture is crucial for maintenance.

** CSS Loading Order

The CSS files are loaded in the following specific order:

1. Theme base styles (from =themes/zen/=)
2. =assets/css/elegant-clean.css= (global overrides and base styling)
3. =assets/css/tags-filter.css= (loaded globally via =layouts/partials/head/styles.html=)
4. =assets/css/archive.css= (loaded globally via =layouts/partials/head/styles.html=)
5. Page-specific CSS (loaded again by individual templates)

** Key Custom CSS Files

*** =assets/css/elegant-clean.css=
- **Purpose**: Global styling overrides and base theme customizations
- **Critical Role**: Contains foundational styles but DELIBERATELY excludes post layout rules to avoid conflicts
- **Maintenance Warning**: This file previously contained conflicting =.post-single-line= rules that were removed to prevent layout conflicts. Do NOT re-add post layout rules here.

*** =assets/css/archive.css=
- **Purpose**: Archive page specific styling
- **Key Features**: 
  - Compact "Jump to Year" section with reduced padding
  - Compact year pills with smaller dimensions
  - Two-line post layout: Title+Date on line 1, Tags (indented) on line 2
  - No box styling around posts section
- **Layout Structure**: Uses =.post-first-line= and =.post-second-line= for hierarchy

*** =assets/css/tags-filter.css=
- **Purpose**: Tag filter page specific styling
- **Key Features**: Identical post layout to archive page for consistency
- **Layout Structure**: Mirrors archive.css post layout exactly

** Post Layout Architecture

The current post layout uses a two-line hierarchical structure:

#+BEGIN_SRC css
.post-single-line {
  display: flex !important;
  flex-direction: column !important;
  /* Creates vertical stacking of two lines */
}

.post-first-line {
  /* Title on left, Date on right */
  justify-content: space-between !important;
}

.post-second-line {
  /* Tags indented with 1rem left padding */
  padding-left: 1rem !important;
  justify-content: flex-start !important;
}
#+END_SRC

** Critical Maintenance Guidelines

*** CSS Conflict Prevention
1. **Never add** =.post-single-line= or =.post-tags= rules to =elegant-clean.css=
2. **Always use** =!important= declarations in page-specific CSS files to override theme defaults
3. **Maintain identical** post layout rules between =archive.css= and =tags-filter.css=

*** Template Structure
- Archive page: =layouts/_default/archives.html=
- Tag filter page: =layouts/tags-filter/single.html=
- Both use identical HTML structure with =.post-first-line= and =.post-second-line= classes

*** Layout Requirements
- **Line 1**: Post title (left) + Date (right)
- **Line 2**: Content type badge + Tags (left-aligned, indented 1rem for hierarchy)
- **No boxes**: Post sections should have no background/border styling

** Favicon Configuration

The site uses a comprehensive favicon setup:

- **Essential files**: =favicon.ico= (multi-size), =apple-touch-icon.png= (180x180)
- **Location**: =static/= directory
- **Configuration**: Set in =config.yaml= as =favicon: "favicon.ico"= and =icon: "favicon-32x32.png"=
- **Optimization**: Files are compressed and optimized for web delivery

** Troubleshooting

*** Tags Not Left-Aligned
- Check if =elegant-clean.css= has conflicting rules
- Ensure =justify-content: flex-start !important= is present in page-specific CSS
- Verify =!important= declarations are not being overridden

*** Layout Breaking on Updates
- Hugo theme updates may introduce conflicting CSS
- Always test archive and tag-filter pages after theme updates
- Check browser developer tools for CSS rule conflicts

*** Performance Considerations
- CSS files are minified and fingerprinted in production
- Favicon files are optimized but could be further compressed if needed
- Monitor total CSS payload size when adding new customizations

** Mobile Navigation and Responsive Design

*** Mobile Menu Configuration
- **Enabled**: =mobileMenu: true= in =config.yaml=
- **Behavior**: Automatically switches from sticky header menu to slide-out mobile menu on screens ≤666px
- **Implementation**: Uses Zen theme's built-in mobile menu with enhanced styling

*** Mobile Menu Fixes Applied
- **Toggle Visibility**: Fixed z-index conflicts (=z-index: 9999=) to ensure hamburger button appears above header
- **Header Positioning**: Set header to =position: static= on mobile to prevent interference
- **Unobtrusive Design**: 75vw width menu with backdrop blur and subtle overlay
- **Touch-Friendly**: 44px minimum touch targets and improved visual feedback

*** Responsive Navigation Features
- **Desktop**: Compact menu items with reduced padding (0.3rem 0.6rem)
- **Mobile**: Slide-out menu (75vw width) with backdrop blur and smooth animations
- **Toggle Button**: Fixed position top-right with glassmorphism styling
- **Sticky Header**: Only active on desktop; disabled on mobile to prevent conflicts
- **CSS File**: =assets/css/responsive-nav.css= handles all responsive behavior

*** Footnote Scroll Offset Fix
- **Problem**: Sticky header obscures footnote targets when clicked
- **Solution**: =scroll-padding-top: 80px= (desktop) / =60px= (mobile)
- **Features**: 
  - Footnote targets are highlighted with fade animation
  - Works with both forward and back footnote links
  - Responsive offset adjustments for different screen sizes

*** Navigation Maintenance Guidelines
- **Mobile Menu Toggle**: Fixed positioned at top-right with backdrop blur
- **Menu Item Spacing**: Controlled via =gap= and =padding= properties in =responsive-nav.css=
- **Scroll Offsets**: Adjust =scroll-padding-top= values if header height changes
- **Mobile Detection**: Uses CSS media queries (max-width: 666px) to match theme's JS breakpoint

** Tag Search Functionality Enhancement

*** Issues Resolved

**** Search Not Working
- **Problem**: Tag search input had no visual effect on available tags
- **Root Cause**: CSS specificity conflict - =.tag-pill { display: inline-block }= overriding JavaScript's =display: none=
- **Solution**: Used =setProperty('display', 'none', 'important')= to force style application

**** Search Algorithm Improvements
- **Original**: Basic substring matching
- **Enhanced**: Multi-priority semantic search algorithm

***** Search Matching Priorities:
1. **Exact word match** at word boundaries
2. **Word prefix match** for CamelCase words  
3. **Substring match** (3+ characters only)
4. **Tag prefix match**
5. **Acronym matching** (2+ characters)
6. **Fuzzy matching** with word boundary detection

***** Features:
- **Multi-word support**: "py data" matches "PythonDataAnalysis"
- **CamelCase aware**: Splits "ProductivityJournal" into ["productivity", "journal"]
- **Case insensitive**: All matching is case-insensitive
- **Length restrictions**: Prevents false positives (e.g., "py" no longer matches "ProductivityJournal")

*** Implementation Details
#+BEGIN_SRC javascript
// Priority-based semantic search in tags-filter.js
shouldShow = searchWords.every(word => {
  const camelCaseWords = originalTagName.split(/(?=[A-Z])/).map(w => w.toLowerCase());
  // Priority 1: Exact word match
  if (camelCaseWords.some(w => w === word)) return true;
  // Priority 2: Word prefix match  
  if (camelCaseWords.some(w => w.startsWith(word))) return true;

});
